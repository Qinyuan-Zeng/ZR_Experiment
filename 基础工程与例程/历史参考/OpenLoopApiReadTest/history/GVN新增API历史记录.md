# GVN 手册外新增 API 使用与验证交接

更新时间：2026年10月28日。适用于本工作区的固高 GVN 新力控接口，以及类似“库已提供实现、公开头文件或编程手册尚未更新”的扩展接口。后续聊天应先参考本文，再按当前任务核实文件与硬件状态。

## 核心结论

编程手册未收录、头文件未声明，不等于函数不存在。技术支持聊天截图明确指定使用 vc_gts，并允许 C++ 按补充说明自行增加声明。函数实现来自厂家 DLL，不需要自行实现厂家内部算法。自行补的是调用接口声明及必要的数据结构，而不是猜测或重写控制算法。

声明缺失、链接失败、运行时找不到入口点、设备返回执行错误，是不同问题，不能混为“API不可用”。即使函数能返回成功，也不等于实际模式切换或力输出已验证。

## 缺少 API 声明时的处理步骤

1. 查找厂家补充说明或经确认的demo，明确精确函数名、返回类型、参数顺序、指针方向、单位及结构体定义。资料存在拼写差异时，以实际导出名称核对，不能直接复制标题中的错字。
2. 静态检查 DLL 的导出表，确认目标函数存在；检查对应导入库符号。检查不需要加载或运行 DLL。导出符号本身不能证明完整参数签名、内部算法或固件支持。
3. 将缺少的声明放在独立扩展头文件，包含原SDK头文件，避免修改原始厂家参考文件。已有结构体、函数不要重复定义。
4. Windows 下沿用厂家 GT_API 宏；本包该宏为 extern "C" short __stdcall。必须匹配参数类型、调用约定、结构体字段顺序及对齐。不要使用 pack(1) 猜测对齐，不要将 Windows long 随意改成64位类型。
5. 选择同一套、同架构的头文件、LIB、DLL。32位工程用x86，64位工程用x64。改用gts库时应改包含和链接配置并重新编译，不能把gts.dll简单放进依赖gxn.dll的旧程序目录就认为完成替换。
6. 编译链接通过后，先验证读取接口及返回码，再进行受限写入读回，最后才验证模式切换、非零输出和工艺性能。每层分别记录证据。
7. 每次记录实际加载DLL路径、设备版本、核号轴号索引、返回码和读回值。读取失败时不能解释缓冲区中的默认零值；返回非零时不能因读回值恰好与原值相同而宣布写入成功。

结构体静态尺寸和偏移检查只能排除部分ABI错误，不能代替厂家确认。本轮 TForceControlPrm 在Windows/MSVC默认对齐下为56字节，feedbackForceK偏移8，outputReverse偏移48；TSwitchLoopParameter为32字节。对应实现见 OpenLoopApiReadTest/gvn_force_api_ext.h。

## 本次新旧库的差异

静态检查发现，vc_gts 的x86/x64 DLL均导出了说明中的12个接口，两套LIB也包含对应符号。但gts.h只声明其中5个，缺少下列7个：

- GTN_SetForceControlParameter / GTN_GetForceControlParameter
- GTN_SetForceCalibrationTable / GTN_GetForceCalibrationTable
- GTN_SetForceLoopPid / GTN_GetForceLoopPid
- GTN_GetForceFeedbackValue

gts.h也缺少 TForceControlPrm 和 TForceCalibrationTable。可以依据补充说明添加所需定义，不必仅因缺声明就认定需要厂家重新发整套SDK。

旧开环demo附带的gxn库采用 Set/GetForceFeedbackComp；新库采用 Set/GetForceCalibrationTable。旧头文件注释controlType闭环为1，而新说明写2。不要混用旧注释、新结构体和新DLL推断语义。

## 控制结构及 demo 的模式切换

用户确认平台为水平直线电机，控制卡运行位置速度双闭环，下层驱动器保持同步周期电流模式。开环力控切换改变的是控制卡输出来源，不应为此自动改变驱动器工作模式。

按新说明：loopMode=2为位置速度双闭环，loopMode=4为力控模式；controlType=0为开环力控。loopMode=3是另外的开环模式，不能无依据替代4。

demo先在双闭环下快进、搜索，调用SetSwitchLoopParameter设置enable=1、mode=0、跟随误差阈值/方向/持续时间、openLoopDac。跟随误差为规划位置减实际位置，条件满足后控制卡自动切入，第一段输出由openLoopDac提供。demo通过enable归零判断完成，停止规划后才调用SetForceValue改变后续输出。

正常回切demo采用enable=1、mode=1、posOffset=-10，保持使能等待完成，然后回退。demo并未先AxisOff。新测试加强为模式与enable双重读回核对；不能仅凭enable归零或Setter返回0断言切换成功。

## 输出单位与标定边界

SetForceValue/openLoopDac在开环时是DAC bit，不是牛顿。CurrentResidualForceCalibration中的400raw正式阈值、500raw预热阈值是电流反馈软件退出阈值，不是驱动器实际限流，也不能当成400/500 DAC bit。

该目录虽然留有4.5A额定电流和1000满量程常量，但实际currentRawToArms函数返回NaN，并注明没有实测安培标定。因此不得据常量宣称400raw=1.8A。电流反馈raw、输出DAC bit、电流残差—接触力模型是三种不同量；现有残差标定不能直接给出新接口的牛顿到DAC指令换算。

非零出力、驱动器硬件限流、DAC到电流映射、实际接触力精度尚未验证。后续聊天不得将本轮读取成功、编译成功或假API模拟成功升级为这些功能已经安全可用。
