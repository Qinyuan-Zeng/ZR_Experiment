# 卡侧 PVT 换向功能验证

使用 `turn_probe` 独立工程入口验证卡侧两段换向。两段的名义位置、速度和加减速度沿用收尾方案。首段加速终点、匀速终点、换向点及第二段对应点合成 7 个 PVT 节点。换向点的速度为零，表中只有一个该节点。C++ 一次下发 7 点，只提交一次启动命令，读回单次循环设置。首段结束由控制卡直接进入下一段。

依据 [GVN 编程手册](../../../产品参考手册/GVN编程手册.pdf) 印刷第 94～97、366～367、369 页。PVT 的单位分别是 ms、pulse 和 pulse/ms，位置由相邻位置和速度作三次插值。梯形段满足 `Δx=Δt(v0+v1)/2`，离线核对了其位置、速度和加速度。手册和编译仅给出命令语义和指令路径，实际固件对小数时刻、换向跟踪、状态回读和停止的行为待实机验证。

| 工程路线 | 位置（pulse） | 两段峰速与加减速度 | 名义换向／完成时刻 |
|---|---|---|---|
| SB-1 | 15,000 → 17,000 → 15,000 | 10、10 mm/s，400、400 mm/s² | 225／450 ms |
| SB-2 | 17,000 → 15,000 → 17,000 | 10、10 mm/s，400、400 mm/s² | 225／450 ms |
| E2-original | 10,500 → 21,500 → 15,500 | 38、12 mm/s，600、400 mm/s² | 352.807／882.807 ms |
| E2-mirror | 21,500 → 10,500 → 16,500 | 38、12 mm/s，600、400 mm/s² | 352.807／882.807 ms |

## 后续现场验证

1. 先核对设备工况和空闲 PVT 表号。用 `freeze --route SB-1` 离线冻结所用程序、表号、响应时间和保护参数。现场操作者明确确认冻结 ID、设备状态及执行范围后，才使用 `capture --route SB-1`。先将轴按现场批准流程停稳于首节点，入口按反馈 ±2 pulse、规划位置 ±1 pulse 核对。程序不自动转场。批前独立读卡通过后仍需键入 `START`。
2. 回放检查是否出现真实双向位移、实际换向位置、两段速度、起始与末端保持、Watch 连续性、SDK 速度和卡时标。换向时刻附近的低速区间单独报出。探针记录计划表、卡侧启动、PVT 状态、到位和末端保持，没有读取原 PVT 节点表的证据。实际运行保护速度为 50 mm/s，目标速度仍按点表。异常时请求平滑停机并记录状态。仅在正常执行已停稳后由程序恢复 TRAP，异常后由现场核对模式及恢复。
3. **人工核对实际波形、卡侧停止行为与模式恢复后**，用 `review --route SB-1 --attempt <编号>` 签署留档。SB-2 同样执行。两个 S-B 审查均有效才允许冻结 E2 原向及镜像工程试验，各自另需现场授权。
4. 工程验证记录在 `turn_validation`。工程试验不进入正式补测或 E 数据。确认卡侧实现、时钟和保护后，再接入正式采集入口并冻结版本。现有生产入口继续拦截 S-B/E2，不自动以工程记录放行 E。

PVT 是卡内轨迹规划模式，运行时仍为位置伺服。试验是否能满足方案所需的无显式停留，以同卡原生 Watch 测量和人工审查为准。
