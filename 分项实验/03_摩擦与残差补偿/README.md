目标：稳态摩擦、必要的动态残差采集、网络训练和完整轨迹验证。

- src：本类实验的多个主运行CPP，同一项目每次选一个入口。

控制台输入少量常用参数，默认值由新平台确认。预热流程待检查，历史与漂移问题按实际证据决定是否分析。

## A0 稳态摩擦预筛

A0 用位置模型扣除空载电流的位置项，在相同位置比较正反向的稳态残差。用 10,000 脉冲/s 与历史 C 做会话对照，用 20,000 检查中速增量，用 5,000 检查低速段形状。每档一个完整往返，用于决定正式 A 的采集点表。

### 1. 编译与离线预览

在 VS 2022 打开 [ZRFrictionCurrent.vcxproj](ZRFrictionCurrent.vcxproj)，选择 Release | x64 并生成。也可在 VS 2022 Developer PowerShell 中从工作区根目录运行：

```powershell
$a0 = '.\分项实验\03_摩擦与残差补偿'
msbuild "$a0\ZRFrictionCurrent.vcxproj" /p:Configuration=Release /p:Platform=x64
$exe = "$a0\bin\x64\Release\a0_scan\ZRFrictionCurrent.exe"
& $exe --plan
```

预览可连续回车采用候选值。第一行 `2,400` 分别是转场速度（mm/s）和加减速度（mm/s²），第二行 `0,32` 是低、高换向位置（mm）。本台 1,000 脉冲/mm。程序预览固定顺序 10,000、20,000、5,000 脉冲/s，每档先正向后反向，合计六趟。按两侧各约 50 ms 内收后，每档的预计匀速窗口均须覆盖 3,500～22,000 脉冲。预览用于确认点表和几何窗口。

### 2. 现场采集

冻结本轮协议 ID、参数和六趟点表。现场确认 Z 就绪、R 固定、限位、急停、抱闸和停车余量。批前独立只读检查状态，从实际停稳位置校核到首个换向点的转场路径及整批停车余量。按 [实机运行约定](../../经验与规则/编程与运行约定.md) 留存批前、批后状态。

```powershell
& $exe
```

显式输入本轮确认的两行参数，核对预览后输入冻结协议 ID，再输入 `START`。运行中按 Q 或 Ctrl+C 可请求程序平滑停机。程序打印会话号，原始 CSV 保存到本目录的 `data/raw`，参数、计划和试次状态保存到 `manifest`。出现异常时保存退出信息并独立检查轴状态。现场条件变化或状态检查异常时停止发起新运动。

### 3. 回放

从工作区根目录运行，使用已安装 NumPy、ReportLab 的 Python 3。将 `<会话号>` 替换为程序输出的 `Session` 值。

```powershell
python "$a0\scripts\a0_replay.py" --session '<会话号>'
```

省略 `--session` 时回放第一阶段 C 会话 Z-C_20261124-165139_02 的开发集，速度为 2,000、10,000、40,000 脉冲/s，每档三个往返。两种回放共用 `position_B_primary_v1` 位置表和第二阶段原 B 矩阵的 fitZero 区间。程序核对会话状态、信号配置、试次用途、完整性和双向配对，保存原始数据哈希。

对每趟扫描按真实时间戳在采样点两侧各取约 50 ms，用编码器位移估计两侧速度、中心速度与加速度。沿用位置表保存的速度容差（10%）、加速度和采样间隙判据，检查运动位、使能、位置模式、报警及限位。选取位移最长的连续单调匀速段，在表内逐样本计算反馈电流减位置项。新 A0 会话要求六趟都完整覆盖 3500～22000 脉冲，每 250 脉冲线性插值，共 75 点。覆盖不足时回放报告试次与实测范围。历史 C 回放沿用共同覆盖裁剪。各位置等权，正负方向按同一组、同一速度和位置配对。独立重复的统计单位为整个往返。惯性敏感度按候选系数区间的最大绝对值乘实测重建加速度绝对值计算，用于估计量级。

结果位于 `results/<会话号>.stage3_A0/`。`pairs.csv` 按往返列出试次号、实测速度、方向残差和惯性敏感度。新会话额外列出各方向的实际匀速覆盖。 `profiles.csv` 保留逐位置配对。 `summary.csv` 按速度汇总方向残差、半差、半和及样本标准差，单往返的标准差留空。 `sources.json` 保存输入和脚本哈希、窗口、网格及新会话的协议 ID。图位于 `data/figures/<会话号>.stage3_A0.svg`。

先与历史 10,000 脉冲/s 档比较。该档半差为 99.75 ± 0.98 raw，正向与反向残差均值分别为 +95.75 和 −103.74 raw。确认对照后，再用同会话 20,000 与 10,000 的差值判断中速增量，并结合 5,000 档检查低速形状。

## 正式 A 恒速摩擦采集

正式 A 已于 2026-11-26 完成。最终协议 `Z-AF-20261126-03` 验收 85 个往返，使用 10,000～22,000 pulse 的 49 点网格。最终汇总、模型及原始记录入口见 [正式 A 结果索引](results/formal_a/Z-AF-20261126-03/README.md)。

### 1. 编译和预览

也可双击 `bin/x64/Release/a_scan/ZRFrictionCurrent.exe` 打开正式 A 菜单。输入 `1` 可离线预览，`2` 只读检查，`3` 冻结，`4` 执行下一批，`5` 查待采，`6` 回放，`0` 退出。

在工作区根目录的 VS 2022 Developer PowerShell 运行以下命令。项目仍默认编译 A0，指定 `EntryPoint=a_scan` 生成正式 A。

```powershell
$a = '.\分项实验\03_摩擦与残差补偿'
$py = 'C:/Users/HYB/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
$run = "$a\scripts\a_formal.py"
msbuild "$a\ZRFrictionCurrent.vcxproj" /p:Configuration=Release /p:Platform=x64 /p:EntryPoint=a_scan
& $py $run --plan --position 0
```

当保护余量要求把换向点内移时，可在离线预览和冻结命令中加 `--grid-lo 10000`。上界仍为 22,000 pulse，网格间隔 250 pulse。参数随协议冻结，回放使用该协议的网格。

离线预览默认显示 0～32,000 脉冲候选行程。可用 `--lo`、`--hi`、`--accel` 和 `--position` 查看其他候选换向点、加减速度及转场。预览预计匀速区间，冻结时另外计算停车余量，实跑还会用实际停稳位置和控制卡平滑停减速度重新检查。

```powershell
$id = 'Z-AF-01'

```

`--state` 只读检查轴和控制卡平滑停减速度。使用现场确认的协议 ID，并将 `--position` 改成用于冻结预览的实际候选起点。冻结保存点表、保护参数、位置表、惯性结果和执行文件的哈希。若候选起点或换向点位于保护边界，必须先按现场流程确认可行起点及换向范围。批前会重新检查，状态或停车余量不合格时不会发出运动指令。冻结后的点表及保护参数以本轮现场确认记录为准。

### 3. 分批运行和续采

```powershell
& $py $run --batch $id
& $py $run --pending $id
& $py $run --replay $id
```

每次 `--batch` 仅取下一组待采项，最多四个往返。输入实际现场会话 ID，按 [实机运行约定](../../经验与规则/编程与运行约定.md) 确认 Z 就绪、R 固定、限位、急停、抱闸和允许执行范围后输入 `READY`。程序先独立读状态并检查转场及整批停车余量，显示点表后输入 `START` 执行。采集完成或中断后独立再读状态，然后回放。中断、限位、控制条件变化或验收异常时，核对现场状态和记录再决定是否续采。

每一对的两趟都完成且实际匀速段覆盖统一网格后才登记通过。半对及原始记录会保留，下次按完整往返重采；同批已通过的其他往返可继续使用。批前批后状态、退出码及验收放在 `manifest/formal_a/<协议ID>/attempts/`。已保存批后状态但尚未入账的批次可用 `--replay` 离线恢复。

### 4. 评价

前四轮 56 个开发往返拟合 F0 库仑和 F1 库仑＋黏性两支模型。4,000、14,000、32,000 脉冲/s 的 12 个整档留出往返用于评价。程序在前四轮全部通过后冻结 F0 和 F1，第五轮使用不同于前四轮的实际独立现场会话 ID，采齐 17 个往返后只做评价。F0 和 F1 正反两支均以实测速度绝对值为自变量，F1 斜率单位为 raw/(1,000 脉冲/s)。

结果写入 `results/formal_a/<协议ID>/`。看 `pairs.csv` 和 `profiles.csv` 检查方向残差和空间分布，用 `middle_speed_by_round.csv` 看逐轮 20,000 档减 10,000 档的半差，用 `model_metrics.csv` 看两种模型的正反向 RMSE、绝对误差 P95 及偏差。与 A0 作对照时按本轮冻结网格裁剪 A0 的 `profiles.csv`，再汇总共同位置，并考虑 A0 只扣位置项的口径。

## B 动态残差实验 V1.1

后续按 2026-11-26 的 `ZR_Stage3_Experiment_B_Plan_V1.1.md` 展开。源文件 SHA-256 为 `3121767D6394E26C2926D1E9CCB134A6E7254C7F89F702EE717E2073156D8AA1`。V1.1 中的轨迹、速度和重复次数是候选设计，正式采集使用现场预检通过后冻结的点表。

1. **B0 先做离线审计。** 按原始完整往返、工况和会话去重，核查真实时间戳、轴状态、信号来源、模型有效域和重复性。分别保留离线参考与只用当前及过去数据的因果特征，先形成历史清单、覆盖、时序诊断、机理残差和补采缺口矩阵。
2. **B1 按缺口补采。** 以 2～40 mm/s、两条候选短路径和 32 个候选工况为基础。每工况目标 5 个完整往返，跨时段安排 3＋2。历史记录按等价路径、有效状态覆盖和独立重复核减。B1 的 320 趟是未核减的计划量。
3. **B2 按 60、80、100 mm/s 逐档验收。** 用冻结 F1 先评估高速外推，桥接工况用来区分速度和路径的影响。沿用 A 的实机保护值作预检查时，60 mm/s 每端约需 6,328 pulse 停车空间，B2 两条候选路径的低端仅有 3,000 或 4,000 pulse。正式高速点表须根据 B2 现场校核重新冻结。
4. **C/D 补齐启停与保持，E 提前预注册。** E 的未见速度、路径、会话和排除规则在训练前冻结，全程留给独立评价。前序模型拟合或选择用过的会话继续作开发或诊断。同一原始往返的派生记录归入同一数据划分。

B 阶段沿用已冻结的 [第一阶段位置表](../01_位置相关空载电流辨识/models/position_B_primary_v1.json)、[第二阶段惯性系数与验收](../02_等效惯性电流辨识/results/d/Z-DP_20261126-095126_343_29884_summary.json) 和 [第三阶段 A 的 F1](manifest/formal_a/Z-AF-20261126-03/models_frozen.json)。位置表插值域为 1～31 mm，已有 F1 独立会话证据覆盖 2～40 mm/s、10～22 mm 的稳定滑动。位置越界、高速外推和近零速单独标记。B0 的时间对齐、缺口和残差审计通过后再定 B1 实机点表。
