## 冻结模型与适用范围

A1、B、D 用编码器实际过点对齐同向的加速与减速轨迹。主结果用 **21 ms** 位置二次拟合估计实际加速度、**5 ms** 中心窗求电流，逐样本扣除 [第一阶段冻结位置表](../01_位置相关空载电流辨识/models/position_B_primary_v1.json)，再计算电流差与实际加速度差。冻结模型为 `ΔI = K_a Δa`，截距为零。

- **冻结系数**为 **3.0306147541113107×10⁻⁵ raw/(脉冲/s²)**，报告值为 **3.637×10⁻⁵ mA/(脉冲/s²)**。a33 按驱动器电机额定电流配置 1.200 Arms 换算，1 raw = 1.2 mA。原始数据和程序协议保留 raw。
- **证据范围**为正向 H1、B 的 400,000～600,000 脉冲/s² 建模中段及 16,000、20,000 脉冲/s 两种匹配速度。D 在单个独立留出工况验收通过，且平均偏高接近偏差上限。冻结值用于匹配点附近的惯性电流预测。
- **整段轨迹的解释**以 C 为边界证据。C 与 B 基于相同的线性惯性假设，C 用 `∫a dt = Δv`，比较速度带内的累计电流差。两带结果都显示 B 系数平均高估实测积分差。速度带边界定位、停留时长差异、位置补偿残差及其他动态分量均可能影响积分，现有结果不足以定量归因。
- **后续建模**固定该系数用于 [摩擦与残差实验](../03_摩擦与残差补偿/README.md)。优先从匀速段辨识速度和方向相关电流。加减速段扣除位置项和惯性基线后，按剩余电流残差分析，其中可能仍含惯性预测偏差。

## 卡侧高速采集探针

[ZRInertiaCurrent.vcxproj](ZRInertiaCurrent.vcxproj) 是第二阶段共用工程。Debug x64 默认选择 [A1](src/a1_matched_pair.cpp)，Release x64 默认选择 [高速采集探针](src/probe_hs_capture.cpp)。后续入口在同一项目下通过 `EntryPoint` 择一编译。工程复用平台调试项目的 `gts.h` 和 x64 `gts.lib`，构建后复制配套 `gts.dll`。

### 现场第一次静止采集

1. 确认 a33 为核 2、轴 1，Z 轴处于现场确认的稳定静止状态，并结束其他使用控制卡或 Watch 的客户端。程序使用核 2 的 Watch 定时组，覆盖该组原有的闲置采集配置，退出时恢复原组选项。轴的使能、抱闸、控制模式和运动状态由现场维持。
2. 在 VS 2022 选 Release x64，按 Ctrl+F5。也可从本目录启动下方的 EXE。回车采用 5 s，允许输入 1～10 s。确认后输入 `START`。Q 或 Ctrl+C 仅结束此次采集。打开 PCIe 连接后，程序读取普通接口，执行 Watch 采集配置，批读数据，最后关闭连接。
3. 先检查摘要的 `clock_matches_ordinary_bracket=1`、`requested_duration_covered=1`，以及缺口、重复和倒序计数均为 0。再比较 `position_watch_*` 与 `position_ordinary_before_after` 的位置量级，以及 `current_watch_*` 与 `current_ordinary_before_after` 的电流符号和量级。若两次普通读数均为 0 或接近 0，静止记录无法验明负号方向。完成状态 `capture_complete_channel_review_pending` 仍需这一步人工确认。
4. 首次静止记录的时钟与通道核对通过后，同一入口可加 `--passive-motion` 旁录人工发起的低档运动片段。采集与运动工具需要能够共用现有卡连接，或由现场已验证的其他控制方式发起运动。静止对照值只在采集前后读取。电流动态更新和相对位置的时延留给运动记录核查。

```powershell
MSBuild .\ZRInertiaCurrent.vcxproj /p:Configuration=Debug /p:Platform=x64
MSBuild .\ZRInertiaCurrent.vcxproj /p:Configuration=Release /p:Platform=x64
.\bin\x64\Release\probe_hs_capture\ZRInertiaCurrent.exe
```

### SDK 核对记录

- 固高《GVN 编程手册》第 21 章和指令 395 将 `GTN_ReadHsOn` 描述为模式 2 寄存器刷新。现场配套 DLL 的 `GTN_ReadHsReadBuffer` 读取固定寄存器区，`count` 为 16 位字数且最大 512，ABI 没有历史帧数输出。本机 `GVNFunctionCase/高速读功能-未完成` 的入口是空壳。采用 Watch 定时组静态采集，按变量批读同一停止后的记录。[厂家在线手册](https://www.googoltech.com.cn/Uploads/file/20250211/20250211154102_81673.pdf)
- 配套 `gts.h` 提供 Watch 变量编码，补充原型来自本机厂家 SDK 的 `E:/A_ZQY/Experiment/参考/friction_ff_compensation/gxn.h`。已核对当前 x64 `gts.dll` 的导出和 `gts.lib` 链接，DLL SHA-256 为 `E06871528FBCB9C94495745ADCE75CC28E1A200CD2C20DEE36F38F04CEB144ED`。厂家振镜调试例程以 `WATCH_GROUP_TIMER`、`WATCH_MODE_STATIC` 和 `interval=0` 配置 Watch。本程序通过 API 配置，现场无需 INI。
- 本程序配置 `WATCH_VAR_PRF_LOOP (1201)`、`WATCH_VAR_ENC_POS (30000)` 和 `WATCH_VAR_ATL_TORQUE (61201)`。轴相关主索引取 1，次索引填 1。手册的 Watch 变量表注明 `PRF_LOOP` 为中断周期计数，普通 `GTN_GetClock` 单位为 ms，`GTN_GetClockHighPrecision` 每中断递增 1。核周期 API 在本机资料中没有可靠的输出单位标注，现场程序先以两种普通卡时钟约 300 ms 的增量比校核 `GTN_GetCorePeriod`，在 µs、ms、s 三种倍率中选择与实测相差不超过 8% 的项。无法确认时结束并保留原始读数及返回码。
- Watch 采用 SDK 默认计数参数 0，由主机到时调用 `GTN_WatchOff`。按 1 起始的变量序号调用 `GTN_ReadWatch`。每列主机缓冲按采集时长加 0.5 s、除以核周期后向上取整，程序上限为 100 万个 `double` 元素。只有三列非空、返回帧数一致、未触及读取上限，且读前后卡侧采集状态一致时才按帧序号合并统计。批读接口没有显式溢出标志，CSV 留 `unavailable`，通过卡时钟、覆盖时长、返回计数和 Watch 状态检查截断或缺口。

## 低档往返旁录与回放

双击 [run_passive_motion.cmd](run_passive_motion.cmd)，或从 VS 工程对应的 Release 输出启动 `ZRInertiaCurrent.exe --passive-motion`。连续两次回车采用 **10 s** 和 **0 → 32 → 0 mm、10 mm/s、400 mm/s²**。输入 `START`，看到「采集已启动，可以开始本次往返」后，操作者通过现场已验证的方式发起运动。提示下方每秒更新剩余时间。若用另一程序发起运动，现场先确认两个程序能同时使用控制卡，且运动程序不会改写核 2 的 Watch 定时组。上述数值随 manifest 记录为预期工况，实际端点和分段由编码器回放判断。

默认档的两程估计约 6.5 s。10 s 记录预留启停和折返时间。2 mm/s 的两程走行约 32 s，需要另行安排录制时长。

```powershell
node scripts/analyze_watch_motion.mjs <session_id>
node scripts/verify_watch_motion.mjs
```

分析脚本读取同名逐帧 CSV 和 manifest，输出到 `results/watch_motion/<session_id>/`。生成的 `summary.md` 含端点、两程位移、覆盖及逐段与窗口统计，`segments.csv` 和 `windows.csv` 分别记录逐段和逐窗数据。诊断图 `diagnostic.svg` 共用卡内时间轴，并放大各方向可识别的最长加减速段。

- 位置按 1000 pulse/mm 换算。每个连续卡时钟段用中心 5 ms 位置线性拟合估速度，再用 5 ms 速度差分估加速度。摘要逐会话记拟合窗、方向/静止速度阈值、加速度阈值、最短阶段与位置容差。阈值之间及边界样本标为过渡。
- 5、15 ms 窗按实际卡内时间从每个已记录帧开始滑动。均为半开区间，末端须落在采集时间范围内。跨时钟断点或跨运动段的窗口保留在 CSV 并标记，分组统计使用段内窗口。跨断点窗口内两侧分别比较相邻帧。最长同值时长按最长连续同值帧数乘核周期计算。
- 变化次数为连续卡时钟上相邻两帧电流 raw 不同的次数。例如 100 帧形成 99 个可比较帧对。反馈刷新后可能仍得到相同量化值，窗口结果描述可观测变化。

离线验收用既有 5 s 静止会话，以及一个 0 → 1 → 0 mm、每 1 ms 切换电流水平、含 40 个缺失 tick 的量化编码器合成往返。静止会话的 100,060 个完整 5 ms 窗均为 100 帧、0 次变化。合成会话复现 ±1 mm 行程和两个方向，逐窗与已知电流阶跃对照，跨缺口窗被单独识别。2026-11-25 另在实际控制卡上验证 10 s 旁录启动提示、倒计时和工况快照，录得的会话仍为静止。
