# 编程与运行约定

每类实验建立一个 .vcxproj 项目，在 src 中并列保存多个有 main 的 CPP。只保留本次入口参与编译，其余入口在项目属性中设置“从生成中排除”，Debug/Release均核对；公共代码正常参与编译。按用途命名入口，例如 read_state.cpp、hold_positions.cpp、scan_velocity.cpp。无需为每条实验另建项目。

启动后的控制台显示本次实验用途和少量常用参数，例如速度、目标位置、重复次数。提供经新平台确认的默认值，回车采用，允许取消。输入检查包含数值有效性、单位与当前已确认范围。显示最终参数后依用户操作执行。程序自动保存参数快照，日常运行无需在外部修改配置文件。硬件网络配置和驱动整定仍在首次调试中单独完成。

参考工程使用 VS v143、x64、Windows SDK 10、C++14、/utf-8，include指向项目sdk，lib指向sdk/x64，链接gts.lib，构建后复制gts.dll和XML至输出目录，调试工作目录为输出目录。具体以现有vcxproj为准，移植时改为相对路径。旧gxn工程与gts工程应分别使用配套头、LIB和DLL。

源码必须连同工程、SDK、配置来源和运行证据一起引用。未完成新台适配的CPP留在历史参考区。正式实验目录暂不放带旧台坐标的运行入口。

## Codex 分批实机运行

现场操作者一次说明本轮协议 ID、允许的批次或完成范围，并确认 Z 已就绪、R 已固定、限位及急停可用、抱闸配置与停车余量适用。Codex 记录该确认，保持现场有人可中止运动。软件状态只用于核对可读条件。历史会话的 START、示例命令以及程序的确认参数均不能代替本轮现场确认。

每批从冻结点表取待采项，主动读卡并保存状态。位置、规划、速度、模式、使能、报警、限位、跟随误差和停稳检查通过后，从实际位置校核到起点的转场以及全批停车余量；满足时由实验程序转场。路径余量不足时保存原因，另行确认初始位置调整方案。严禁借点动绕过失败的路径检查。

批后再次独立读卡，再离线回放并核对接受项。批次出错时仍尽可能保存批后状态与可恢复数据，停止继续发令。正常批次可在同一轮授权内自行接续；条件变化、故障或异常中断应先核对原因和现场状态。每批留存协议、参数、状态、会话号、退出码和回放结论。
