# 控制卡驱动器与接口经验

旧台证据见[接口交接](../基础工程与例程/历史参考/GVN新增API使用与验证交接.md)和[实测进展](../基础工程与例程/历史参考/OpenLoopApiReadTest/研究进展.md)。

## 可以复用的方法
- 新增API缺声明时核对厂家文档、DLL导出符号、结构体大小、偏移和调用约定。
- gts头/LIB/DLL按架构与版本配套，运行时记录实际DLL路径。
- 每个接口检查返回值。开卡、网络初始化成功与总线真正连接分开判断。
- 切换任务类型mode与轴状态loopMode分开解释，通过任务完成位和实际模式确认。
- 读取失败记未知，不能把初始化的0误认为有效状态。
- DAC指令、反馈raw、安培和牛顿分别定义，分别标定。

## 新台 Z 轴反馈电流换算

2026-11-26 经用户确认，新台 Z 轴 a33（核 2、轴 1）的 `GTN_GetAtlTorque` 与 Watch `WATCH_VAR_ATL_TORQUE` 有符号反馈读数，以采集时 DriverStudio「电机参数 → 额定电流（Arms）」为基准。当前配置为 **1.200 Arms**，1000 raw 对应 1.200 A。换算保留符号：`I[A] = raw × 1.200 / 1000`，即 **1 raw = 1.2 mA**。产品规格图列出的 Z 轴额定电流 **1.6 A** 单独作为产品参数记录。更换轴或修改额定电流、反馈通道配置后，按对应会话的配置核定比例。[厂家反馈电流换算说明](../产品参考手册/读驱动器电流说明.pdf) · [产品规格图](../产品参考手册/ZRADS-6-16B-S40-EC.pdf)

## 新台 Z 轴 Watch 定时采集

2026-11-25 已在 a33（核 2、轴 1，固件版本读数 100）验证位置与电流的卡侧历史帧采集。复用时从[高速采集探针](../分项实验/02_等效惯性电流辨识/src/probe_hs_capture.cpp)取配置与批读流程；配套 SDK 的 `GTN_ReadHsReadBuffer` 用于读固定寄存器区。接口来源和配套库版本见[第二阶段 SDK 核对记录](../分项实验/02_等效惯性电流辨识/README.md)。

1. 读取 `GTN_GetCorePeriod`，用 `GTN_GetClock` 的毫秒增量除以 `GTN_GetClockHighPrecision` 的中断计数增量，校核一个 tick 的时长。本机实测 50 µs/tick；保存核周期原值、单位和校核结果。
2. 确认核 2 定时组空闲，选择 `WATCH_GROUP_TIMER`、`WATCH_MODE_STATIC`、`interval=0`，计数取 SDK 默认值 0。同组添加 `WATCH_VAR_PRF_LOOP`（1201，中断计数）、`WATCH_VAR_ENC_POS`（30000，编码器脉冲）和 `WATCH_VAR_ATL_TORQUE`（61201，有符号电流 raw）。本机三个通道配置的主、次索引均为 1。读回变量配置后调用 `GTN_WatchOn`。
3. 调用 `GTN_WatchOff` 后，按从 1 开始的通道序号用 `GTN_ReadWatch` 分列批读。按录制时长和核周期预留缓冲。确认各列返回成功、非空、帧数相同且未触及读取容量，批读前后 Watch 计数与头指针一致，再按帧序号合并。退出时恢复原先选中的 Watch 组。[实机配置、读回与返回码](../分项实验/02_等效惯性电流辨识/manifest/Z-HS_20261125-094343_092_16300.txt)
4. 保存原始 tick、位置、电流和批读记录，按 32 位计数回卷处理时间轴，检查重复、逆序、缺失 tick 和首末帧覆盖时长。接口无显式溢出标志，记录为 `unavailable`。跨缺口窗口单独标记。采样能力与整段运动覆盖的实测依据见[采样与实验数据规则](采样与实验数据规则.md)。

## 旧台验证范围
旧台曾完成2→3→2模式切换、正向短脉冲DAC映射及2ms三角波发送。三波形中的三角波和正弦形有实测，S型和最新退出改动整轮仍需补实机验证。1ms加密采样尝试曾超期。详见原日志。
原代码channel=5、CORE=2、AXIS=1等只是来源配置。新平台的电流环/速度环/位置环参数均待现场记录，不能从旧台得到新台已验证的PID数值。
竖直Z轴的重力与抱闸使能/释放顺序、零电流与撤使能行为应结合实际设备确认。驱动器旧参数/XML可用于比较，载入前核对新硬件。
